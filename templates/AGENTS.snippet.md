## CMS integration

Preserve the target's routes, frontend design, content, drafts and versions. Follow its authorization, language, licensing, Git and acceptance rules; merge this section without overwriting unrelated instructions.

Use localized functional labels, validation and accessibility feedback. Do not invent decorative headings, translations or explanatory filler. Keep the native form as the sole persistence writer; canvas edits use explicit typed mappings. Existing images and links remain the editing targets, preview preserves their original behavior.

Audit exact dependency versions, transitive licenses and notices before adding them. Restricted/unknown source or generated provenance needs explicit review; research does not authorize copying. Preserve required copyright and license files. The owner's code license is a separate decision.

Use isolated test data. Do not modify real content or expand roles to make a fixture pass. A build or in-memory event check is not frontend acceptance. Keep temporary verification artifacts out of the project after use; retain required runtime and license files.
